# Isaac Arena — асимметричный 2 vs 3 twin-stick roguelike

Браузерная игра: два Айзека проходят этаж, три игрока вселяются в мобов и мешают.
Авторитетный сервер, бинарный протокол, Canvas2D, ноль зависимостей на клиенте.

* Внутреннее разрешение 480×270, апскейл целочисленным `transform: scale()` + `image-rendering: pixelated`.
* Клиентский бандл **13.9 КБ gzip** (бюджет 120 КБ), спрайтшит **4.1 КБ** PNG-8 (бюджет 256 КБ).
* Симуляция 30 Гц на сервере, рендер 60 FPS с интерполяцией на 100 мс и client-side prediction.
* Вход без кодов и лобби: открыл вкладку — уже играешь.

---

## Запуск

```bash
npm i && npm run dev
```

`npm i` собирает атлас и бандл (postinstall), `npm run dev` поднимает esbuild в watch-режиме
и сервер на `http://localhost:8080`. Открой несколько вкладок — они попадут в одну сессию.

Прочие команды:

```bash
npm run build   # продакшн-сборка в public/
npm start       # только сервер (нужен готовый public/)
npm run atlas   # перегенерировать spritesheet
npm run bench   # проверка бюджетов памяти и размера, exit 1 при превышении
```

## Управление

| Действие | Клавиатура и мышь | Сенсор |
|---|---|---|
| Движение | `WASD` | плавающий стик на левой половине |
| Стрельба (Айзек) | `←↑↓→` или ЛКМ по курсору | плавающий стик на правой половине, огонь автоматом |
| Способность (монстр) | `Пробел` или ПКМ | круглая кнопка справа снизу |
| Рывок (монстр) | `Shift` | вторая кнопка |
| Бомба (Айзек) | `E` | та же круглая кнопка |
| Звук / музыка / справка | `M` / `N` / `Tab` | — |

Телефон и ПК играют в одной сессии: протокол один и тот же, устройство на сервере
никак не различается. Сенсорный стик движения даёт те же восемь направлений, что
и клавиши, стик прицела — полные 360° (как мышь). В портретной ориентации
показывается просьба повернуть телефон: игра рассчитана на горизонтальный экран.

## Правила

**Айзеки (2 игрока, кооп).** 6 сердец, i-frames 0.8 с, слёзы с параметрами
damage / firerate / range / speed / shotspeed. Предметы стакаются: пробитие,
наведение, тройной выстрел, яд, отскок, крупные слёзы. Бомбы ломают камни и
вскрывают секретные комнаты. Айзек на нуле сердец ложится и поднимается через 8 с,
если напарник жив. Победа — убить босса этажа.

**Монстры (3 игрока, PvP).** Каждый вселён в живого моба текущей комнаты.
Движение то же, плюс одна способность архетипа и рывок:

| Архетип | Способность | КД |
|---|---|---|
| Ползун | разгон и таран | 2.4 с |
| Плевун | три дуговых снаряда | 2.0 с |
| Делитель | добровольное деление на два осколка (−40 % hp) | 6.0 с |
| Прыгун | прыжок-телепорт с уроном по площади при приземлении | 3.2 с |
| Щитоносец | блок фронтального урона на 1.5 с | 4.0 с |
| Босс | радиальный залп | 3.0 с |

Смерть тела — мгновенное переселение (< 250 мс): ближайший свободный моб → спавн
нового за счёт бюджета волны → режим духа со свободной камерой, пока бюджет не
восстановится в следующей комнате. Урон игроков-монстров ×0.7 от ИИ-версии,
запас hp ×1.35, одновременно в комнате не больше трёх игроков-монстров.
Победа — обнулить сердца обоим Айзекам одновременно.

После раунда — мгновенный рестарт с новым seed и сменой сторон.

## Архитектура

```
/client   index.html main.js render.js input.js net.js pool.js gen.js audio.js
/shared   protocol.js constants.js sim.js   ← общая детерминированная симуляция
/server   index.js session.js matchmaker.js ai.js
/tools    build.mjs atlas.mjs bench.mjs
```

* `shared/sim.js` — единственный источник правды по физике, коллизиям и генерации
  этажа. Исполняется и на сервере (авторитет), и на клиенте (prediction).
* Коллизии: uniform grid 16×16 px, counting sort без аллокаций; тайлы — раздельное
  разрешение по осям с соскальзыванием по углам.
* Сущности — SoA в TypedArray, `MAX_ENTITIES = 512`, free-list вместо `new`.
* Комнаты генерируются из seed (mulberry32). В памяти живёт только текущая комната;
  покинутая сворачивается в 32-байтную запись (зачищена, посещена, битовая маска
  разрушенных камней на 135 тайлов, флаги лута).
* Частицы — кольцевой буфер на 256 без спавна поверх лимита.
* Звук — процедурный WebAudio (осцилляторы + один буфер шума), ноль аудиофайлов.
* Спрайтшит рисуется кодом в `tools/atlas.mjs` и кодируется вручную в PNG-8
  (IHDR/PLTE/tRNS/IDAT) через `node:zlib`.

### Матчмейкинг

`GET /` отдаёт игру, WS-хендшейк на `/ws` сразу вызывает `joinAny()`:

1. сессия с `players < 5` и `state = running` → подключить;
2. Айзеков меньше двух → слот Айзека (вытесняет ИИ-бота, наследуя его прогресс),
   иначе слот монстра (вселение в свободного моба);
3. свободных сессий нет → создать новую и стартовать немедленно, добив состав ИИ.

Отключение: сущность Айзека мгновенно переходит под ИИ, тело монстра
освобождается и возвращается серверному ИИ. Никаких экранов ожидания.

Ник генерируется детерминированно из UUID в `localStorage` — по проводу идут два
байта индексов, ни одной строки. Аккаунтов нет.

### Античит

Валидация на сервере: монотонность `seq`, темп стрельбы (клиент не решает, когда
вылетает слеза), кулдауны способностей, скорость (сервер сам интегрирует движение
из битов инпута), rate-limit 90 пакетов/с на соединение, не больше 4 соединений
с одного IP.

## Деплой

Одна команда:

```bash
flyctl deploy
```

(`fly.toml` уже в репозитории; при первом разе — `flyctl launch --no-deploy --copy-config`.)

Для Render: подключить репозиторий, `render.yaml` подхватится сам (Docker-runtime,
healthcheck `/health`).

Локальная проверка образа:

```bash
docker build -t isaac-arena . && docker run --rm -p 8080:8080 isaac-arena
```

### Масштабирование

Сессия целиком живёт в одном процессе и не делит состояние ни с кем: **sticky-сессии
не нужны**, достаточно обычного L4/L7-балансировщика. Горизонтально —
`flyctl scale count N`; каждый инстанс держит собственный пул сессий (до 64) и
принимает игроков, пока в его сессиях есть места. Один процесс на shared-cpu-1x
тянет порядка 60 сессий (300 игроков) при тике ~0.2 мс на сессию.

Ограничение: игроки не могут выбрать конкретный инстанс — это осознанный размен на
отсутствие лобби и кодов. Если понадобится «играть с другом», добавляется
`?s=<id>` и роутинг по `fly-replay`.

## Бюджеты

`npm run bench` поднимает сервер, гоняет headless-браузер 20 секунд как настоящего
клиента и забирает `performance.measureUserAgentSpecificMemory()`. Падает с кодом 1
при превышении: heap вкладки 150 МБ, бандл 120 КБ gzip, атлас 256 КБ,
сессия сервера 2 МБ.

## Транспорт

Основной — `uWebSockets.js` (optional dependency). Он не собран под musl (alpine)
и не поддерживает Node 24, поэтому `server/index.js` содержит встроенный
RFC 6455-транспорт поверх `node:http` и переключается на него автоматически.
Оба пути реализуют один интерфейс `conn.sendBin(u8, len)`; протокол и логика общие.
Чтобы принудительно получить uWS — базовый образ на glibc (`node:20-slim`) и
`npm i` без `--omit=optional`.
